Component Syncer for Room Combiner

Plugin version 1.1.0.0 · This document written for 1.1.0.0
White Label AV · whitelabelav.co.nz

Plugin description

Component Syncer keeps a group of like Q-SYS components in step with each other, driven by the state of a Room Combiner. You nominate one component per room; when the Room Combiner joins rooms together, the nominated components in that group are synchronised, and a change made to any one of them is pushed to the others in the same group.

Which controls are synchronised is chosen per component type at design time, and which control property carries the change (String, Value, Position or Boolean) is selectable at runtime.

Setup and configuration

  1. Place a Room Combiner in your design and configure its room count and walls as usual.
  2. Place Component Syncer and set its Rooms property to match the Room Combiner's room count. A mismatch is reported through the Status indicator rather than being silently tolerated.
  3. Give every component you intend to synchronise a Code Name (Script Access), since the plugin addresses them by name.
  4. Select the Room Combiner in Room Combiner Name. The combo box is populated with every room_combiner component in the design.
  5. Enter the Code Name of the component to be synchronised for each room, under Synced Component Names. You need at least two. You do not need one for every room — a design may legitimately have rooms with nothing to sync. An unrecognised name turns its box red.
  6. Once a valid component is found, Detected Component Type shows the type being matched and Synced Controls lists every control in that type. Tick the controls to synchronise.
  7. Choose which property carries a change under Sync By Property. This is a radio group — one property at a time — and defaults to String.
Important notes
  • All nominated components must be of the same type. A mismatch sets Status to Fault and names the offending components.
  • Avoid selecting indicator-only controls (LEDs, meters) under Synced Controls. They report state rather than accept it, and syncing them achieves nothing.
  • Components of the same type may still carry different control sets — Custom Controls, Matrix Mixers and Crossovers with differing properties are the common cases. Syncing across these works but is the least-tested path; proceed with care.
  • The plugin's Rooms property must match the Room Combiner's room count. It does not adapt automatically.
  • No instance limit, and no embedded components — so no impact on the design's channel or player budget.
  • Control selections persist across reboot and redeploy in a hidden non-volatile control, keyed to the detected component type. Changing the component type resets the selection to defaults.

Usage

Operate the Room Combiner as you normally would. When room groupings change, every synchronised component in a group is brought to the state of the lowest-numbered room in that group that holds a valid component. From then on, a change to any control in the group propagates to the rest.

Release notes

1.1.0.0

  • Behaviour change — Sync By Property is now a radio group. Previously the four buttons were independent, so a change could be pushed as several properties at once. Exactly one is now active, defaulting to String. A design saved by 1.0.x with more than one selected resolves to the first in the order String, Value, Position, Boolean.
  • Synced Component Name boxes enlarged, and wrapped into a new row every four rooms, so a high room count grows the panel downwards instead of off to the right. All fields below the grid now share its width.
  • Corrected a misspelled key in the NonVolatileMem control definition (ControType → ControlType), which had left its control type unspecified since 1.0.0.
  • An unconfigured plugin now reports Compromised, not Fault. A freshly placed instance is a setup task, not a failure, and no longer raises a red alarm. The plugin also no longer sets Initializing, which the Status Reporting standard reserves to the application.
  • Fixed the status flickering between Initializing and OK at high room counts. Every edit to a component name box triggered a full re-initialise, so loading a 256-room design ran 256 of them back to back. Re-initialising is now debounced into a single pass.
  • Fixed a runaway propagation loop. Writing a synced value fired the target control's own handler, which re-broadcast it to the whole group again. At 256 rooms a single fader move recursed until the Lua stack was exhausted. Propagation is now guarded and skips writes to controls already holding the value: one move across 256 rooms costs 256 writes rather than tens of thousands.
  • Further work reduction for large designs: wall changes are debounced, stale event handlers are torn down on re-initialise instead of being left live, redundant sorting and per-target control reads were removed, and all diagnostic printing is now gated behind the new Debug Print property.
  • Room number labels widened to fit three digits, so rooms above 99 are no longer clipped.
  • The Synced Controls list is now sorted by name. It previously took Lua's pairs() order, which is not guaranteed stable between runs, so the list could reorder itself across a restart — and an entry's stored index could disagree with its position, toggling the wrong control.
  • Adopted the White Label AV brand header on the plugin control panel.
  • Panel restyled onto the shared brand colour, type and spacing tokens.
  • PluginInfo completed with Manufacturer, Model, IsManaged and Type, as the Verification Rubric requires. Authorship updated to White Label AV.
  • Fixed unpredictable layering on the control panel: ZOrder was previously set on some elements and not others, which Q-SYS leaves undefined. Every element now carries a distinct value.
  • Fixed the Room group box and per-room text boxes drawing with no stroke colour, the result of a reference to an undefined colour constant.
  • Source split into a multi-file PLUGCC layout under src/. No runtime behaviour change.

1.0.1

  • Added an event handler for Room Combiner wall configuration changes.
